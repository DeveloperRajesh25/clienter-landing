# Search Console & Bing Webmaster checklist

**Written:** 4 October 2026, against the `seo/overhaul` branch.
Everything here needs an account and a login, so none of it was done for you — this is the list to
work through once, then the weekly routine.

---

## 1. One-time setup

### Google Search Console

- [ ] **Verify the domain property** `clienter.co.in`, not the URL-prefix property. A Domain property
      covers `http`, `https`, `www` and every subdomain in one place, which matters here because the
      app lives on `app.clienter.co.in` and the business pages are proxied onto the apex. Verification
      is a DNS TXT record at your registrar.
- [ ] **Also add `app.clienter.co.in`** as its own property. It is a different site with different
      jobs; mixing its reports into the marketing site's will confuse both.
- [ ] **Paste the verification token into the site as a backup.** `src/app/layout.tsx` has the slot,
      commented out at the bottom of the `metadata` export:
      `verification: { google: '…' }`. DNS verification alone is enough, but the meta tag survives a
      DNS change.
- [ ] **Submit both sitemaps:**
      - `https://clienter.co.in/sitemap.xml` — 162 URLs before this branch, **152 after** (the 11 tag
        and 3 category archives were removed, 3 plural alternatives pages added). A drop here is
        expected and correct, not a regression.
      - `https://clienter.co.in/profiles-sitemap.xml` — generated by the **app** and proxied onto this
        domain. Already declared in `robots.txt`. If it errors, that is an app-repo issue (see
        `docs/needs-owner-input.md`).
- [ ] **Check the "Domain" setting is not geo-targeted to India.** International Targeting is
      deprecated in the UI, but if a legacy setting exists on an old property it will still be
      working against the global positioning this overhaul just put in place.
- [ ] **Request indexing** via URL Inspection for the pages where it matters most, in this order:
      `/`, `/pricing`, `/features`, `/compare/clienter-vs-honeybook`, `/compare/clienter-vs-bonsai`,
      `/alternatives/honeybook-alternatives`, `/alternatives/bonsai-alternatives`,
      `/alternatives/dubsado-alternatives`, `/client-management-software`, `/crm-for-freelancers`.
      The first three because their titles, descriptions and locale signals all changed; the next five
      because they are new or substantially rewritten.

### Bing Webmaster Tools

- [ ] **Verify the site and import from Search Console** — Bing supports a one-click import, which
      saves doing the sitemaps twice. Worth the ten minutes: Bing powers ChatGPT's web results, so it
      is not just 3% of search traffic any more.
- [ ] Submit the same two sitemaps.
- [ ] Check **IndexNow**. Bing's instant-indexing API is free and genuinely fast. Not implemented in
      this repo; logged in `docs/needs-owner-input.md` as a small, high-value addition.

### Validation, once deployed

- [ ] **Rich Results Test** (`search.google.com/test/rich-results`) on one page of each type:
      `/` (Organization, WebSite, SoftwareApplication, FAQPage), `/pricing` (Product with **two**
      AggregateOffers, USD and INR — this is new and worth confirming renders), a comparison page
      (BreadcrumbList, FAQPage), a blog post (Article with a Person author).
- [ ] **Confirm the duplicate is gone.** `/pricing` used to emit `SoftwareApplication` twice. The Rich
      Results Test should now show it once.
- [ ] **Check a draft post is excluded.** Open `https://clienter.co.in/blog/agency-pricing-models`,
      confirm the amber draft banner, and confirm `noindex` in the page source. It should not appear in
      the sitemap, `/blog`, or `/rss.xml`.
- [ ] **PageSpeed Insights** on `/`, `/pricing` and `/compare/clienter-vs-honeybook`. Targets:
      LCP < 2.5s, INP < 200ms, CLS < 0.1. The one to watch is **INP on the homepage** — Lenis smooth
      scroll wraps the whole app and the journey section maps scroll to 21 scenes. It was built to
      quantise scroll updates specifically to avoid this, but that is a design intention, not a
      measurement.
- [ ] **Social card check.** The OG locale changed from `en_IN` to `en_US` and several titles and
      descriptions changed. Run `/` and `/pricing` through a social debugger and clear the cache so
      shared links do not keep showing the old copy.
- [ ] **Confirm `www` still 301s to the apex**, and that the redirect survived the deploy.

## 2. The weekly five minutes

Same order every week. The point is noticing a change, not reading everything.

1. **Pages report → Not indexed.** Is the count falling? Which reason is growing? "Crawled – currently
   not indexed" on a new page is normal for a few weeks. The same status on a page that used to be
   indexed is a signal.
2. **Performance → Queries, last 7 days vs previous 7.** Look for queries where impressions are
   rising and position is poor — those are pages one good edit away from traffic.
3. **Performance → Pages.** Any page that lost more than ~20% of clicks week on week. Check whether
   its title or description changed recently; this overhaul changed a lot of them.
4. **Experience → Core Web Vitals.** Any URL group moving from Good to Needs improvement.
5. **Enhancements (Breadcrumbs, FAQ, Merchant listings).** New errors after a content change usually
   mean a config file is missing a field.

**Monthly, in addition:** the GA4 numbers in `docs/analytics-plan.md` §5, and a scan of the top 20
queries for ones the site ranks for but has no page about — those become entries in
`docs/content-plan.md`.

## 3. What specifically to watch after this branch deploys

This overhaul changed a lot at once, so these are the readings that tell you whether it worked.

| What changed | What to watch | Expected direction |
|---|---|---|
| 127 titles no longer truncated | CTR in Performance → Pages | Up, within 2–4 weeks |
| Locale signals: `en-IN` → `en` | Impressions from US, UK, AU, CA (filter by country) | Up, slowly — this is a trust signal, not a switch |
| 14 thin archives noindexed | Not-indexed count; sitemap URL count | Count drops to 152; "Excluded by noindex" rises by 14 — both correct |
| USD offers in the Product schema | Merchant listings enhancements; Rich Results Test | Should validate; a US searcher should see a dollar price |
| `/pricing` rewritten | `/pricing` clicks and CTR | Watch for a drop — the strikethrough prices were doing CRO work, even though they were unsupportable |
| 8 comparison titles de-Indianised | Those pages' impressions, by country | India impressions may dip; US/UK/AU should rise. **This is the trade and it was made on purpose.** |
| 3 new plural alternatives pages | Indexation, then impressions for "<competitor> alternatives" | Indexed within 2 weeks, impressions from week 3–4 |
| 5 posts expanded, `updated` dates set | Those posts' positions | Up or flat; a refresh rarely hurts |

**The one to be honest about.** De-Indianising eight comparison titles may cost India impressions
before it gains anything elsewhere. That was a deliberate trade for a global audience, recorded here
so that if India traffic dips in week two nobody concludes the overhaul broke something. If after
eight weeks India has dropped and nothing else has risen, the reversible move is to put India back in
the `metaTitle` of the two or three pages where India genuinely was the stronger market, rather than
reverting the lot.

## 4. Things it is tempting to do and should not be done

- **Do not request indexing repeatedly** for the same URL. It does not help and the quota is small.
- **Do not resubmit the sitemap** to "force" a recrawl. Google re-reads it on its own schedule; the
  submission is one-time.
- **Do not judge anything at four days.** A change of this size needs four weeks before the numbers
  mean anything, and positions genuinely do wobble in both directions first.
- **Do not add a second sitemap index** yet. 152 URLs is far below any limit; splitting adds moving
  parts for no crawl benefit. Revisit near five figures.
- **Do not use the URL removal tool** on the noindexed archives. They should be crawled and seen to be
  noindex, which is how they fall out of the index cleanly and keep passing link equity to the posts.
